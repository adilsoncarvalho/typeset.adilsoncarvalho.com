# Typst API — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Ticket:** NT-typst-api

**Goal:** A document author configures the template. They never write `#set par()`, `#set text()` or a literal millimetre.

**Architecture:** Every `#set` currently written in a demo moves into a named function in `implementations/typeset.typ`. The demos then read as a document a person would write. A gate holds the demos to that, so the next demo cannot reintroduce a raw `#set`.

---

## Why this exists

Nine demos configure the layout inline. That inverts the point of a template:
a change to the indent, the leading, or the alignment means editing every
document that shows it, instead of one function. The demos also drift from the
real implementation, because they *reimplement* it rather than call it — the
two-column demo hand-rolls `#columns(2, gutter: 6mm)` beside a `two-column()`
function it never uses.

Every function below is **singular** from birth. The existing plural names
(`quotes-*`, `frontmatter-*`) are the separate rename group's problem; nothing
new should add to it.

## Global constraints

- `spec.json` is the source of truth. No function hardcodes a value the spec
  owns — derive it, and gate it, the way Group 4's margin constants now are.
- Every new function needs a demo that uses it, and every demo that used to
  hand-roll the same thing must be converted in the same task.
- `tools/check.mjs` must gain the gate before or with the change, and the gate
  must be watched failing.
- No version bump. No tag. 2.0.0 stays unshipped.

## Task 1: The tab scroll

**Files:** `specimen.css`, `tools/check.mjs`

Diagnosed, not guessed. `.tabs input` is `position: absolute` with `top`/`left`
`auto`, inside a flex container with `align-items: flex-end`. An absolutely
positioned child of a flex container takes its static position from the
container's alignment — so each hidden radio sits at the **bottom of `.tabs`**,
and `.tabs` contains the panes. Clicking a label focuses that radio, the browser
scrolls it into view, and the page jumps to the bottom of the example.

- [ ] **Step 1: Reproduce it first.** Open `index.html`, click a Typst tab, and
      confirm the jump. Then confirm the cause: temporarily give `.tabs input`
      `top: 0; left: 0` and check the jump stops. If it does not stop, the
      diagnosis above is wrong — say so and diagnose it properly before fixing.

- [ ] **Step 2: Fix.** `.tabs { position: relative; }` and
      `.tabs input { top: 0; left: 0; }`, so the radio is pinned to the tab
      strip rather than floating to the bottom of the pane.

- [ ] **Step 3: Gate the invariant.** `.tabs input` being `position: absolute`
      while `.tabs` is not positioned is the bug. Assert in `check.mjs` that
      whenever `.tabs input` declares `position: absolute`, `.tabs` declares
      `position: relative` and the input declares both offsets. Watch it fail by
      removing `position: relative`, then restore.

- [ ] **Step 4: Commit.**

## Task 2: Measure as a named value

**Files:** `implementations/typeset.typ`, `src/demos/foundation.typ`, `tools/check.mjs`

`src/demos/foundation.typ` opens `#block(width: 126mm)` and `#block(width: 170mm)`.
Both are literals, and the second is the full text block — which moved when the
margins changed in Group 4.

- [ ] **Step 1: Export the measures.** Derived from `spec.json`, never typed:

```typst
// foundation.rhythm.measure_mm
#let measure-standard = 126mm
// the measure modifiers CSS already names --measure-narrow / --measure-wide
#let measure-narrow = ...
#let measure-wide = ...
// the full text block: paper width less twice the default margin
#let measure-full = ...
```

- [ ] **Step 2: A function that applies one.**

```typst
#let measured(width: measure-standard, body) = block(width: width, body)
```

- [ ] **Step 3: Convert the demo.** `src/demos/foundation.typ` becomes
      `#measured[…]` and `#measured(width: measure-full)[…]`. No millimetre
      appears in the demo.

- [ ] **Step 4: Gate.** Each exported measure must equal what `spec.json`
      derives. Watch it fail by changing one, then restore.

- [ ] **Step 5: Rebuild, check, commit.**

## Task 3: Paragraph blocks

**Files:** `implementations/typeset.typ`, `src/demos/paragraphs.typ`, `tools/check.mjs`

`src/demos/paragraphs.typ` writes
`#set par(spacing: leading-for(1.45), first-line-indent: (amount: 1.5em, all: false))`.
That is the template's business.

- [ ] **Step 1: Two functions**, named for the spec elements they implement
      (`paragraphs-spaced`, `paragraphs-indented`):

```typst
#let block-spaced(body)    // separated by space, no indent
#let block-indented(body)  // indented continuation, no space
```

      Both take their values from the spec, not from the numbers currently in
      the demo. Read `paragraphs-spaced` and `paragraphs-indented` in
      `spec.json` and use those.

- [ ] **Step 2: Convert the demo** to `#block-indented[…]`. The spaced case is
      the document default, so it needs no wrapper — say that in the demo note
      rather than wrapping it for symmetry.

- [ ] **Step 3: Gate** the two functions' values against the spec. Watch it
      fail, restore.

- [ ] **Step 4: Rebuild, check, commit.**

## Task 4: Alignment

**Files:** `implementations/typeset.typ`, `src/demos/justification.typ`, `tools/check.mjs`

`src/demos/justification.typ` has three blocks, each setting `par.justify` and
`text.hyphenate` by hand. The document-wide default already exists as
`typeset(justified: …)`; what is missing is the per-block override.

- [ ] **Step 1: Two functions.**

```typst
#let justified(indented: false, lang: "en", body)
#let ragged-right(indented: false, lang: "en", body)
```

      `lang` is what drives hyphenation, so a German document gets German
      hyphenation without the author knowing `text.hyphenate` exists. Justified
      text without a hyphenation language is the third demo case — the rivers —
      so `lang: none` must be expressible and must be what produces it.

- [ ] **Step 2: Convert the demo.** Three blocks become
      `#ragged-right[…]`, `#justified[…]`, `#justified(lang: none)[…]`.

- [ ] **Step 3:** Confirm `typeset(justified: …)` and these compose — a
      `#ragged-right` block inside a justified document must be ragged, and
      vice versa. Render and check, do not assume.

- [ ] **Step 4: Gate** that the demo contains no `#set par` or `#set text`.
      Watch it fail, restore.

- [ ] **Step 5: Rebuild, check, commit.**

## Task 6: The bibliography

**Files:** `implementations/typeset.typ`, `spec.json`, `src/demos/bibliography.typ`, `src/demos/bibliography.html`, `typeset.css`, `tools/check.mjs`

This was agreed in your first review and never built. `src/demos/bibliography.typ`
is still twelve lines of `#set` followed by four hand-formatted strings, so the
author owns the citation format — which is exactly backwards.

- [ ] **Step 1: The block.**

```typst
#let references(title: [References], body)
```

      It owns the size, leading, spacing, hanging indent and the heading. The
      heading is the `bibliography-heading` element Group 4 deferred — add that
      element to `spec.json`'s `bibliography` section here, and add it to
      `templates.two-column.spanning.always`, which is where it was meant to be.
      That closes the *Carried forward* item.

- [ ] **Step 2: The entry.**

```typst
#let reference(
  author: none, title: none, edition: none,
  publisher: none, year: none, note: none,
)
```

      It composes the entry: author roman, title italic, the rest in order, the
      punctuation between them the template's business and not the author's.
      `note` carries an annotation — the Ruder entry in the current demo has one,
      so the shape must survive the conversion.

- [ ] **Step 3: Convert the demo** to `#references[ #reference(…) … ]`, with the
      same four works and the same annotation.

- [ ] **Step 4: The CSS side.** `.ts-bibliography-entry` exists; the new heading
      needs `.ts-bibliography-heading`, and `bibliography.html` needs to show it.
      The naming gate enforces the pairing, so this is not optional.

- [ ] **Step 5: Gate** that the demo contains no `#set`, and that the spanning
      list's new id spans in both implementations — Group 4's gate already
      checks that list, so the new entry rides it. Confirm it does rather than
      assuming; the Typst arm has an explicit render-checked list that will need
      the new id adding.

- [ ] **Step 6: Rebuild, check, commit.**

## Task 7: The two-column demo

**Files:** `implementations/typeset.typ`, `src/demos/two-column.typ`, `tools/check.mjs`

`src/demos/two-column.typ` hand-rolls the entire template: `#set text`,
`#set par`, `#columns(2, gutter: 6mm)`. Beside it sits a real `two-column()`
function the demo never calls. The two can drift, and the 6mm is a literal.

The obstruction is real: `two-column()` is a show-rule template that calls
`set page()`, and a demo snippet renders inside a container where `set page()`
cannot take effect. That is the same constraint that broke the letter page.

- [ ] **Step 1: Split the template.** `two-column()` currently does page
      configuration *and* body composition. Extract the composition:

```typst
#let two-column-body(gutter: none, front: none, doc)
```

      `two-column()` keeps its signature and its refusal arithmetic, and calls
      `two-column-body()` for the part that is not the page. The demo calls
      `two-column-body()` directly. Both then share one implementation, which is
      the point.

- [ ] **Step 2: Convert the demo.** No `#set`, no literal gutter. The front
      matter stays as it is — it already uses real functions.

- [ ] **Step 3:** Confirm `example-two-column.typ` still renders byte-identically.
      The split must be a refactor, not a change. If the output moves, the split
      is wrong.

- [ ] **Step 4: Gate** that `src/demos/two-column.typ` contains no `#set` and no
      `#columns(`. Watch it fail, restore.

- [ ] **Step 5: Rebuild, check, commit.**

## Task 8: The blanket gate

**Files:** `tools/check.mjs`

Tasks 2-7 each convert one demo. This stops the next one regressing.

- [ ] **Step 1:** Assert that **no** file under `src/demos/*.typ` contains
      `#set par(`, `#set text(` or a bare millimetre literal. A demo is a
      document a reader will copy; if it configures the layout, the template has
      failed to cover that case.

- [ ] **Step 2:** Any demo that genuinely must configure something is evidence
      of a missing function, not a reason to weaken the gate. If you hit one,
      **stop and report it** rather than adding an exemption list — an exemption
      list is how this gate dies.

- [ ] **Step 3:** Watch it fail against a demo before Task 2's conversion, then
      confirm green after all conversions.

- [ ] **Step 4: Commit.**

## Deliberately not in this plan

- **The singular rename** (`quotes-*` → `quote-*`, 12 prefixes, 58 elements) and
  `#quote(type:)`. Named separately because it is a mechanical sweep across all
  three vocabularies with its own codemod, and mixing it with new API design
  makes both harder to review. Every function added here is already singular.
- **A headless browser for the CSS conformance arm.** Recorded under *Carried
  forward* in the design doc; still a decision, not a task.
